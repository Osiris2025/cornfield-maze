2. M31 — THE LANE BLENDS BY TRANSPARENCY, NOT GEOMETRY
=============================================================================
Todd, 2026-09-25: "the path way should not be layered, it should be blended via transparancy. the path
is currenly bubbly and janky."

He was looking at a preview, but the built game has the same defect and your own report names the cause:
"Blend method: geometry." `GroundLaneMesh` pulls the lane's boundary vertices inwards on the mask, so the
join is a CUT LINE with polygon facets — look at `artifacts/review/world/m29-ground-edge.png`: the lane
sits on the field like a plate, with a hard jagged border. A margin that wanders 0.42 m is still a cut,
not a fade. Geometry is not transparency.

What to do: blend the lane into the field through ALPHA.
1. `Assets/Resources/Ground/T_Ground_LaneAlpha.png` is the fade as a strip: **U runs along the lane, V
   across it**, solid in the middle, gone at both edges, with fine grain breaking the ramp. Import it
   Non-Color, sRGB off, Repeat, alpha NOT treated as transparency (it is data).
2. Map the lane mesh's UVs so **V crosses the lane** and drive the lane material's alpha from that
   strip. The lane material must be **Alpha Blend**, not Opaque and not Cutout. If URP/Lit cannot carry
   a separate alpha map, multiply it in a small in-house Shader Graph or via vertex alpha — but the
   RESULT is non-negotiable: **no hard line, no blobs, no visible edge where the layer stops.**
3. **Constant half-width.** A lane does not pulse; a low-frequency wobble on the width is what made
   blobs. The dissolve comes from the fade plus FINE grain, not from moving the edge around.
4. The geometric jitter may stay as a coarse guide if it helps, but it is no longer the boundary. If it
   fights the fade, delete it and say so.
5. **Do not change**: the lane's navigable footprint (M22's lane-centring fix, the corridor constraint),
   the eat sequence, the HUD, the maze layout, M26's threat term.

Evidence: re-shoot `m29-ground-lane.png`, `m29-ground-field.png` and a NEW edge close-up framed like the
current `m29-ground-edge.png` so the two can be compared side by side, plus
`artifacts/m31-lane-blend-report.txt` carrying: the blend mode actually set on the material, the alpha
map's import settings read back, the measured transition width in metres, and the frame cost of turning
blending on for 477 lane pieces (overdraw is real on a phone — measure it, do not assume it).

3. M32 — THE GROUND CATCHES THE MOONLIGHT
=============================================================================
Todd, 2026-09-25: "can you use the PBR files for reflections off the moonlight?" Today it does not:
`Materials.cs` still sets `_Smoothness` to a constant per material and the roughness maps never reach
the shader. URP/Lit cannot take a standalone roughness texture, so the builder now emits URP's
metallic/smoothness map:
1. `T_Ground_Field_M.png` / `T_Ground_Lane_M.png` — RGB = metallic 0 (ground is a dielectric, no metal
   in it), **A = smoothness**. Add them to `CornMazeGroundImport.cs` as Data maps: Non-Color, sRGB OFF,
   and make sure Unity does not treat that alpha as transparency.
2. Wire to `_MetallicGlossMap` with `_SmoothnessTextureChannel = 0` (metallic alpha) and
   `_Smoothness = 1`.
3. **Keep the normal maps bound.** They are what breaks the highlight into grain; a reflective floor
   without normals is a mirror blob, worse than no reflection.
4. The moon is already a directional light (`MoonLight`, amber->blue, shadows off), so specular needs no
   shadow pass. Measured smoothness: lane mean 0.28 with 7.1% of the surface above 0.40 (the loose
   stones), field 0.17 with damp patches the least matte part. If the result looks like polished glass,
   the fix is the roughness numbers, not the light.

Evidence: night frames shot with the moon BEHIND the camera's shoulder so its reflection is in frame,
and a MEASURED before/after in `artifacts/m32-reflection-report.txt` — mean luminance in the reflection
band with the metallic map bound versus unbound. "It looks shinier" is not evidence.
